# My method

How I work inside `method.md`. Personal: copy this to `my.method.md`,
which git ignores, and make it yours. Where it and `method.md`
disagree, `method.md` wins or gets a proposal.

The experience. It holds on any surface.

- I say the feature or the change where I work with the AI.
- When I have to review something, it comes to me as a document. The
  same gesture for a plan, a feature file or a diff.
- A review shows the current state: what changes, what is still open,
  then the part as it would read. No rounds, no history of the review.
  It is work in progress until I approve; what we settled is recorded
  once, at the end.
- I read, select the text I have a remark on, add a comment, and speak
  it through Wispr Flow. I send every remark at once.
- My approval is the approval to edit. Nothing is edited before it.
- I review a teammate's work the same way. There the remarks are
  kept: they go to the merge request as comments.

The surface today. It may change; the experience should not.

- My environment is Claude Code in VS Code. Everything I need is
  there: the files, the AI's thinking and logs, and what is waiting on
  me.
- A document to review arrives as a plan in plan mode. Approving the
  plan is the approval.
